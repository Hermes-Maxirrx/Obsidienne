# Comment réviser avec ce coffre

1. **Choisis une question.** Par exemple : « pourquoi une commande a besoin d'un état ? » ou « comment un événement peut-il être traité deux fois ? ».
2. **Lis une note courte.** Reformule la définition et le piège sans regarder la réponse.
3. **Ouvre le vrai code.** Chaque fiche indique un chemin dans un dépôt local ; ouvre le fichier et vérifie le comportement dans ses tests ou son guide. Une note n'est pas la source de vérité du projet.
4. **Refais un exemple.** Sur une branche ou dans un environnement jetable, jamais sur la production. Compare ensuite avec les tests et la documentation du dépôt. Pour Azure, ne crée ni ne détruis de ressources sans autorisation et estimation.
5. **Relie les notions.** Suis les wikilinks « À relier » plutôt que d'étudier un langage en silo.

Les fiches distinguent les **sources**, le **comportement observé** et les **limites**. Les chemins `/home/max/...` sont ceux de ce serveur. Si un dépôt change, relis son README avant de réutiliser une commande ou un résultat de test. Aucun chiffre de tests ancien n'est une preuve de CI actuelle.
